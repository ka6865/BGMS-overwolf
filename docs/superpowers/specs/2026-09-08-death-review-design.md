# BGMS 짧은 사망 복기 설계

작성일: 2026-09-08. 상태: 구현 준비용 설계안. 이번 산출물은 설계와 실행 계획이며 기능 구현·공개 배포 완료를 뜻하지 않는다.

## 제품 목표와 첫 범위

비전: 매치가 끝나면 복기할 장면을 바로 찾아주고, 다음 판에서 바꿀 행동 하나를 정해주는 앱.

첫 단계 M1은 **완료된 경기의 공식 사망 시각을 기준으로 직전 최대 30초를 지도에서 복기**하는 경험이다. 기존 세션 카드 → 리플레이 연결을 재사용한다. 수동 북마크, 개선 목표 추적, 스쿼드 댓글, 영상 동기화는 각각 독립 후속 단계다.

## 확인한 구현 기준

| 저장소 | 조사 기준 | 확인 사항 |
| --- | --- | --- |
| BGMS-overwolf | `2bee92e`, 앱 0.5.1 | 기존 기능 테스트 85개 및 실행 폴더 빌드 통과. 실제 Windows/PUBG 검증은 미완료 |
| BGMS 웹 `pubg-map-app-local` | fetch 후 `origin/main` = `9884f5b` | 로컬 HEAD `ddd7020`은 원격과 1 ahead / 79 behind. 로컬 main에 그대로 작업하지 않는다 |

코드 사실:

- 앱 `overwolf-app/gep-state.js`: `appendTimeline`의 `t`는 로컬 `Date.now()`와 GEP `matchStart` 수신 시각의 차이다. 공식 시간축과 일치한다는 보장이 없다.
- 타임라인은 먼저 들어온 40개까지만 보관한다. 40개 이후 사망 이벤트는 누락될 수 있다.
- 앱은 첫 `matchEnd` 뒤 세션 요약을 큐에 넣는다. 이후 별도 콜백에서 오는 사망·순위가 이미 만든 요약에 들어간다고 보장할 수 없다.
- 웹 `lib/overwolf/session-view.ts`: 공식/임시 매치 ID 구분, `buildReplayPath`, 세션 묶음 집계가 이미 있다. 새 기능으로 다시 만들지 않는다.
- 웹 `app/replay/3d/page.tsx`: 공식 데이터를 읽어 `PlayerTrajectory.deathTimes`와 재배치 시각을 만들고, `trackingPlayer`, 재생·일시정지, 기존 `t` 쿼리 진입을 지원한다.
- `lib/replay/replay3dHelpers.ts`에 기존 생존 상태·시간·자기장 헬퍼가 있다. 새 사망 구간 선택은 별도 작은 순수 모듈에 둔다.
- 현재 변환된 리플레이 이벤트에 `LogMatchEnd`가 전달되는지는 확인되지 않았다. `MapReplayHandler`가 원문 모든 이벤트를 그대로 전달하는 구조가 아니므로 원문 공식 스키마만 보고 필드 존재를 가정하지 않는다.

## 접근 방식 비교

| 방식 | 장점 | 비용·제약 | 결정 |

| GEP 시간 보정·수집 형식부터 확장 | 이후 북마크 정렬에도 활용 가능 | 중도 실행·시계 변경·이벤트 순서·양쪽 스키마 검증 필요 | M2 선행 검토 |
| 영상 녹화와 지도 동기화부터 구현 | 사용자 시야까지 복기 가능 | 권한·저장 공간·동의·성능 검증 범위가 큼 | M5 |

## 공통 제약

- Overwolf 앱은 영어 기본, 한국어 명시적 선택을 유지한다. 웹은 기존 한국어 UI를 따른다. 새 코드 주석은 한국어로 쓴다.
- M1은 `lib/pubg-analysis/*`, `app/api/pubg/*`, 분석 버전과 AI 코칭 API를 수정하지 않는다. 기존 함수를 읽고 호출하는 것은 허용한다.
- M1은 새 GEP feature, 권한, DB 테이블, 세션 payload 키, 의존성, 자동 분석·자동 조회 스케줄러를 추가하지 않는다.
- GEP 사망/`matchEnd`/로비 복귀/순위는 경기 전체 종료의 증거로 사용하지 않는다.
- 전체 경기 종료와 공식 데이터 준비가 기존 서버 경로에서 확인된 경우에만 새 복기 모드를 활성화한다. 클라이언트 쿼리나 사용자 입력으로 이 조건을 만족시킬 수 없어야 한다.
- 준비 여부를 확인하려고 브라우저나 앱에서 PUBG API를 직접 호출하지 않는다. 기존 웹 조회·캐시·제한 경로를 유지한다.
- 종료 근거가 기존 경로에서 입증되지 않으면 M1 배포를 보류하고 별도 서버 계약 변경안을 작성한다. 금지된 파이프라인을 임의로 수정하지 않는다.
- PUBG 데이터 핵심 기능을 구독자 전용으로 잠그지 않는다. 실시간 적 위치, 데미지/DPS, 분석 원인 단정은 추가하지 않는다.

## 사용자 흐름

1. 기존 세션 카드에서 `사망 장면 복기`를 선택한다. 공식 매치 UUID와 닉네임이 유효한 경우 링크를 제공한다. GEP 사망 개수나 타임라인 존재를 필수 조건으로 삼지 않는다.
2. 경로는 기존 `matchId`, `nickname`, `platform`에 `review=death`를 더한 `/replay/3d`다. 기존 일반 리플레이 링크와 `t` 동작은 유지한다.
3. 기존 텔레메트리 요청을 한 번 수행한다. 새 모드를 위한 중복 조회·주기적 polling을 만들지 않는다. 준비되지 않았으면 이유와 사용자 재시도 동작을 표시한다.
4. 경기 완료 조건을 검증한 후 공식 데이터에서 대상 플레이어를 정확히 식별한다. 정규화된 닉네임의 완전 일치만 허용하고 부분 일치로 다른 사람을 선택하지 않는다. 동명이인 등 불명확한 결과는 선택 실패다. 이 닉네임은 인증된 계정 신원이라는 뜻이 아니다.
5. 유효한 공식 사망 시각을 정렬·중복 제거한다. 기본은 마지막 사망이며, 여러 번 죽고 복귀한 경기는 `1번째 사망`, `2번째 사망` 선택을 제공한다. 마지막 사망 뒤 생존 복귀가 있어도 실제 사망 장면으로 복기할 수 있다.
6. 선택한 사망 D의 구간은 `[max(0, D - 30000), D]`다. 시간 단위는 ms다. 최초 진입 시 시작점에서 **일시정지**하고 플레이어를 추적한다. 사용자가 `30초 복기 재생`을 누르면 기본 1배속으로 재생한다.
7. 사망 시각에 정확히 멈춘다. `다시 보기`는 구간 처음으로, `전체 경기 보기`는 구간 제한 해제와 일반 재생으로 이어진다. 구간 밖으로 사용자가 탐색하면 복기 모드를 종료한다.

자동 진입 재생 대신 일시정지로 시작하는 것은 이번 설계 제안이다. 준비 여부·대상 장면을 확인한 뒤 사용자가 재생하도록 한다.

## 표시 내용과 실패 처리

| 조건 | 동작 |
| --- | --- |
| 공식 사망 확인 | 기존 지도 동선·자기장·플레이어 추적과 사망 순번·구간 표시 |
| 사망 기록 없음/우승 생존 | `확인된 사망 장면이 없습니다`와 일반 리플레이 연결 |
| 닉네임 불일치/중복 | `이 경기에서 플레이어를 확인할 수 없습니다`; 다른 플레이어 자동 선택 금지 |
| 잘못된 ID/임시 ID | 복기 링크 생성 안 함. URL 직접 입력도 기존 검증 적용 |
| 사망 시각 NaN·음수·재생 종료 뒤 | 해당 시각 제외. 가짜 사망 시각으로 clamp하지 않음 |
| 경기 준비 미확인 | 구간/전체 적 위치를 새 복기 모드에서 렌더하지 않고 준비 안내 |
| 지원하지 않는 맵 | 기존 맵 지원 안내를 재사용. 빈 지도를 성공으로 표시하지 않음 |
| 요청 교체·뒤로가기 | 기존 request token/abort를 유지하고 구간·추적 상태를 초기화 |
| 과거 링크 `t`와 `review=death` 동시 입력 | 유효한 새 복기 모드가 우선. 실패 시 `t`를 사망 시각으로 사용하지 않음 |

팀원 거리 수치, 엄폐·시야·의도·사망 원인 해석은 M1에 포함하지 않는다. 현재 좌표는 맵 크기를 반영한 변환 좌표이므로 거리 단위 검증 없이 미터 수치를 제시할 수 없다. 기존 공식 데이터 지도 표현부터 제공한다.

## 변경 경계

웹 저장소에 추가:

- `lib/replay/deathReview.ts`: 공식 사망 목록 정규화, 구간 선택, 재생 구간 종료 계산.
- `components/replay/DeathReviewControls.tsx`: 순번·재생·다시 보기·전체 보기 UI.
- `tests/replay-death-review.test.ts`: 경계·복수 사망·플레이어 선택 테스트.

웹 저장소 수정:

- `lib/overwolf/session-view.ts`, `tests/overwolf-session-view.test.ts`: 복기 링크 생성과 기존 링크 호환.
- `components/overwolf/OverwolfSessionList.tsx`: 기존 카드의 복기 진입 버튼.
- `app/replay/3d/page.tsx`: 기존 요청/렌더 루프와 복기 상태 연결.

앱 저장소에서는 이번 설계·계획·공식 노트·검증 문서만 갱신한다. M1에 앱 코드 변경은 필요하지 않다.

## 선행 검증과 완료 조건

- 먼저 기존 웹 서버의 공식 텔레메트리 응답이 완료된 경기에서만 제공되는지 코드 경로와 실제 완료 경기 표본으로 입증한다. HTTP 200 하나나 비어 있지 않은 이벤트만으로 판정하지 않는다.
- 공식 데이터 변환 결과에서 본인의 사망이 `kill` + `victim` + `relativeTimeMs`로 전달되는지 검증한다. 원문 `LogPlayerKillV2`를 UI가 받는다고 가정하지 않는다.
- 사망 시각 20,000ms → 0~20,000ms; 120,000ms → 90,000~120,000ms. 복수 사망/재배치, 사망 없음, 시간 누락, 불일치 플레이어를 검증한다.
- 재생 중 프레임이 구간 끝을 넘으면 끝 시각에 멈춘다. 페이지 재렌더로 반복 seek하거나 지도를 다시 만들지 않는다.
- 기존 `t=420` 링크와 일반 리플레이의 동작을 회귀 검증한다.
- 같은 완료 경기·같은 장비에서 기존 일반 재생과 복기를 비교한다. 새 반복 네트워크 요청 0건, 숨김 상태 불필요 반복 처리 0건, WebGL 컨텍스트 중복 생성 0건이 기준이다. FPS/메모리는 측정값으로 기록하고 개선을 미리 주장하지 않는다.
- Windows Overwolf 실제 세션 → 웹 → 공식 사망 복기 1회, 일반 사망·복귀 후 재사망·사망 없음 시나리오를 확보한다. 실게임 없이 자동 테스트만으로 출시 완료 처리하지 않는다.

## 후속 단계의 준비 범위

| 단계 | 제공 가치 | 구현 전에 확정할 계약 |
| --- | --- | --- |
| M2 수동 북마크 | 게임 중 궁금했던 순간을 사후 복기 | 기존 40개 상한의 우선순위, 북마크 상한, 시계/중도 실행, 전송 전 이벤트 마감, 서버 kind 허용 목록, 단축키 충돌. 실제 시간 정렬 전 자동 정확 시점 연결 금지 |
| M3 다음 5판 목표 | 분석을 다음 행동으로 연결 | 기존 분석 결과에서 관측 가능한 목표 1종 선택, 5판의 모드·맵·유효 표본 정의, 사용자 선택 보관·해제. 새 분석기부터 만들지 않음 |
| M4 스쿼드 복기 | 같은 장면을 함께 검토 | 공유 범위, 식별·접근 권한, 댓글/도형 수정·삭제, 신고·만료 정책 |
| M5 영상+지도 | 실제 시야와 전체 경기 맥락 연결 | 사용자 선택 영상, 시간 보정, 지원 포맷, 저장 위치·용량·삭제, 권한·opt-in. 외부 앱 자동 연동 API 가정 금지 |
