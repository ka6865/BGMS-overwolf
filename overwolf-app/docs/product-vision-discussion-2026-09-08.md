## 당시 답변 원문

제 추천은 **BGMS를 “매치가 끝나면 복기할 장면을 바로 찾아주고, 다음 판에서 바꿀 행동 하나를 정해주는 앱”으로 발전시키는 것**입니다. 녹화나 숫자 통계보다 현재 BGMS의 지도 분석과 잘 연결되고, 차별화할 여지가 큽니다.

2026년 9월 8일 기준 공식 스토어와 개발사 자료를 비교했습니다. 아래 기능은 공개 자료 기준이며, 각 앱을 직접 설치해 실게임 검증한 결과는 아닙니다.

| 앱 | 제공하는 주요 기능 | BGMS가 참고할 점 |

Insights는 Overwolf판과 독립 실행판이 함께 있어, [PUBG 전용 소개 페이지](https://insights.gg/games/pubg)의 최신 기능이 Overwolf판에도 모두 동일한지는 별도 확인이 필요합니다.

과거에 검토했던 **Ouch**는 자동 사망 리플레이가 좋은 참고 사례지만, 스토어 표시 업데이트가 2021년이라 현재 정상 운영 여부를 확정하기 어렵습니다. **Match Bar**도 PUBG 공식 소개에는 남아 있지만 최신 운영 상태를 확인하지 못했습니다. 따라서 최근 업데이트가 확인된 앱들과 구분하는 편이 정확합니다. [Ouch 스토어](https://www.overwolf.com/app/mao-tou_projects_ltd-ouch), [PUBG 공식 추천 앱](https://developer.pubg.com/featured_apps?locale=en)

또한 **지도 리플레이 자체가 BGMS만의 기능은 아닙니다.** Overwolf 외부에도 Chicken Dinner와 PUBGMaps의 지도 리플레이가 있습니다. BGMS의 차별점은 지도 제공에서 한 단계 더 나아가야 합니다. [Chicken Dinner](https://chickendinner.pubgmeta.com/), [PUBGMaps](https://pubgmaps.gg/replay)

**현재 우리에게 있는 기능**

저장소와 구현 문서 기준으로 정리하면 다음과 같습니다.

| 영역 | 현재 BGMS 기능 |
|---|---|
| 게임 중 보조 표시 | 헤드샷 수, 최장 킬 거리, 기절·게임 단계 등 상태 표시, 종료 후 순위 정보 |
| 앱 사용 편의 | 단축키, 창 위치·투명도 설정, 영어 기본 및 한국어 선택, 진단 화면 |
| 매치 종료 후 연결 | 사용자 동의 기반 세션 요약 전송, 실패 시 로컬 큐 보관·재시도 |
| 웹 복기 | 세션 기록, 주요 이벤트 타임라인, 해당 매치·시점의 지도 리플레이 연결 |
| 연속 플레이 정리 | 여러 경기를 플레이 세션으로 묶어 경기 수·킬·헤드샷·순위 등을 정리 |

이미 **게임 → 세션 요약 → 웹 타임라인 → 지도 복기**라는 연결이 있습니다. 다만 Windows Overwolf와 실제 PUBG에서의 최종 검증, 스토어 출시는 아직 별도 단계입니다.

지금 가장 보강할 부분은 “정보를 더 표시하는 것”보다 **사용자가 무엇부터 보고, 무엇을 배워야 하는지 알려주는 것**이라고 봅니다.

**추가 기능은 다음 순서로 제안합니다.**

1. **“사망 전 30초 복기” — 가장 먼저 추천**

   매치 종료 후 `마지막 교전 보기`를 누르면 사망 직전 구간을 지도에서 바로 재생합니다. 기존 시점 링크를 발전시켜 이동 경로, 당시 자기장, 팀원과의 거리처럼 확인 가능한 근거를 함께 보여줍니다.

   예를 들어 “사망 직전 팀원들과 얼마나 떨어져 있었는지”를 바로 확인하게 하는 방식입니다. 단순히 “엄폐가 부족해서 죽었다”처럼 데이터로 확인할 수 없는 원인을 단정하면 안 됩니다.

   **좋은 이유:** 기존 지도와 타임라인을 활용하면서, 복기를 시작하는 수고를 크게 줄입니다. 공식 매치 데이터가 준비된 뒤 제공하고, GEP와 공식 리플레이의 시간 정렬을 먼저 검증해야 합니다.

2. **“이 장면 나중에 보기” 단축키 — 작은 기능으로 큰 사용 이유**

   게임 중 판단이 애매했던 순간에 단축키를 누르면 시각만 북마크합니다. 매치 종료 후 그 지점의 지도 복기로 연결합니다.

   킬이나 사망이 없어도 “여기서 밀었어야 했나?”, “이 이동이 맞았나?” 같은 순간을 사용자가 직접 남길 수 있습니다. 처음에는 영상 녹화 없이 시작할 수 있습니다.

   **좋은 이유:** 자동 이벤트는 결과를 기록하지만, 북마크는 **사용자가 궁금했던 순간**을 기록합니다. BGMS 앱을 설치하고 켜둘 이유가 생깁니다.

3. **“다음 5판 목표 하나” — 분석을 실제 개선으로 연결**

   기존 분석·코칭 결과에서 사용자가 목표 하나를 고르게 하고, 다음 경기들에서 관련 근거를 비교합니다.

   예를 들어 “첫 교전 때 팀과 떨어지는 상황 줄이기”를 선택하면 이후 경기에서 해당 상황을 돌아보게 합니다. 무조건 점수를 매기기보다는 모드·맵·표본 수를 함께 보여주는 편이 좋습니다.

   **좋은 이유:** 일회성 분석을 반복 사용으로 연결합니다. 새로운 AI 분석기를 만드는 것보다 기존 결과를 행동과 후속 확인에 연결하는 것이 우선입니다.

4. **“스쿼드 같은 장면 복기” — 친구와 함께 쓰는 기능**

   같은 매치의 같은 시점을 링크로 열고, 지도 위에 간단한 화살표나 의견을 남깁니다.

   “왜 혼자 들어갔어?”라는 말싸움 대신, 당시 위치와 이동 순서를 보면서 이야기할 수 있게 합니다.

   **좋은 이유:** 개인 분석을 팀의 반복 사용으로 확장합니다. 다만 공유 범위와 계정·접근 권한 설계가 필요한 후속 기능입니다.

5. **“영상 + 지도 동기 복기” — 장기적으로 가장 매력적인 확장**

   영상에서는 내가 실제로 본 장면을, 지도에서는 매치 전체 맥락을 함께 확인합니다.

   처음부터 자체 녹화기를 만들기보다, 사용자가 가진 클립을 선택하고 지도 시간과 맞추는 작은 형태부터 검토할 만합니다. Outplayed 등과의 자동 연결은 실제 연동 API와 권한을 확인한 뒤 판단해야 합니다.

   **좋은 이유:** 영상만으로 놓치는 주변 상황과 지도만으로 알 수 없는 시야·조작 상황을 함께 볼 수 있습니다. 다만 저장 공간·성능·권한 부담이 있어 앞선 기능보다 뒤에 두겠습니다.

다음 버전에서 하나만 고르면 **1번 ‘사망 전 30초 복기’**입니다. 그다음 **2번 북마크 → 3번 목표 추적** 순서를 추천합니다. 성공 여부도 표시 항목 수보다 **매치 종료 후 실제 복기를 연 비율과 다시 복기하러 온 비율**로 판단하는 게 좋겠습니다.

신규 제안은 현재 승인된 범위를 넘어서는 부분이 있어 구현 범위를 정한 뒤 진행해야 합니다. 이번 비교 근거와 우선순위는 [확장 로드맵](/Users/kangheesung/10-19_개발/13_프로젝트/13.01_PUBG_지도_서비스/bgms-overwolf-app/overwolf-app/docs/extension-roadmap.md)에 기록해두었습니다.
